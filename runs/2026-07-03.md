**Scarcity and urgency, HONEST only.** Source: web search on Hormozi's `$100M Offers`
scarcity/urgency framework (search 2026-07-03; loxie.app, minchowcoders.com, and
thepowermoves.com summaries).

Takeaways:
1. Hormozi names three legitimate scarcity/urgency levers: limited supply ("only N spots"),
   limited time ("price rises Friday"), limited bonuses ("first N buyers get X"). Each is a
   real, verifiable constraint, not a UI trick.
2. The load-bearing rule: honest scarcity outperforms fake scarcity over time. Every claim
   must be checkable and true, or it is the fastest way to destroy trust in a brand that
   otherwise leans on premium, plain, calm-conviction copy (this page's whole voice).
3. Scarcity = how many. Urgency = how long. They are different levers and shouldn't be
   blurred into one vague "act now."
4. Applying this to VanguardOS: the Launchpad today has none of the three real constraints.
   Unlimited digital delivery (no supply cap), no announced price-increase date, and the
   bonus stack is not time-boxed. Inventing any of the three would violate the "no fake
   countdown, no invented stock" hard lock and this run's own honesty principle.
5. Decision: did NOT add scarcity/urgency copy this run. The only honest lever available
   right now (a real rolling-cohort or a real bonus-stack expiry) does not exist as a
   business fact yet, so writing it would be fiction. Logged as a backlog idea instead, for
   if/when Jamil sets up a real constraint (e.g., "the $811 bonus stack is Product 1's
   launch stack; future VanguardOS systems ship their own stack" is true today per the
   Launchpad's own portfolio positioning and could become a real, honest scarcity angle IF
   Jamil confirms he wants the bonus stack itself framed as launch-specific).

## 2. Files changed

**`src/routes/+page.svelte`** (1 file). Focus area: Core Web Vitals / LCP, applying the
already-studied Value-Equation "Time Delay" principle (2026-06-29) to the page's actual
render speed rather than its copy.

- **Hero `<h1>`, ~line 701.** Before: shared the `.hero-item` class with every other hero
  element, which `onMount()`'s `motion.animate('.hero-item', {opacity:[0,1], ...}, {delay:
  stagger(0.13)})` starts at inline `style="opacity: 0"` and fades in only after JS
  hydrates and the stagger reaches it. This `<h1>` is by a wide margin the largest painted
  text block above the fold, i.e. the page's actual LCP candidate. Chrome's LCP algorithm
  does not count an element as painted while it is at `opacity: 0`, so gating the single
  biggest element behind a post-hydration JS fade was directly inflating measured LCP, and
  literally made real visitors wait longer to see the headline than necessary, the opposite
  of the "collapse Time Delay" principle this project already committed to. After: removed
  from `.hero-item` (and its inline `opacity: 0`), given a new `.hero-h1` class instead. The
  headline now paints at full opacity on the very first frame, no JS dependency.
- **New CSS, `.hero-h1` + `@keyframes heroH1In`, in the component `<style>` block.** A
  transform-only entrance (`translateY(14px) → 0`, 0.7s) that never touches `opacity`, so
  the motion/premium feel is kept but the element is never invisible, hence always a valid
  LCP candidate. Respects `prefers-reduced-motion` (animation disabled).
- **Specimen-modal fonts, script + `<style>` (~lines 22-40, ~2130-2140).** Before: two
  Google Fonts / Fontshare font families (Fraunces, Source Serif 4, Geist, Geist Mono,
  Clash Display, Satoshi) were loaded via a render-blocking `@import` at the top of the
  component's global `<style>` block, fetched on literally every pageview, even though they
  only paint inside the click-to-inspect Typography/Palette specimen modal (a small
  fraction of visitors ever open it). After: moved to a `loadSpecimenFonts()` helper that
  injects the two stylesheet `<link>` tags into `document.head` lazily, the first time
  `openSpecimen()` is actually called. Removes two blocking font fetches from the critical
  rendering path for every visitor who never opens the modal.

No numbers changed: `$811` (3 occurrences) and `$129` (20 occurrences, both unchanged from
before this run's edits, the small drift from the 07-02 log's "21" reflects two unrelated
manual H1-copy commits Jamil/Antigravity made directly between runs, not anything in this
diff) verified untouched by `git diff`. FAQ array and FAQPage JSON-LD untouched this run.

## 3. Concrete improvements (2, both Core Web Vitals)

1. **Hero `<h1>` no longer gated behind a post-hydration JS opacity fade.** *Why it lifts
   conversion / SEO:* this is the page's real LCP element. Every millisecond it stays
   invisible after first paint is a millisecond added to a Core Web Vital Google uses for
   ranking, and a millisecond a real buyer stares at a blank hero before reading the offer.
   This is the "Time Delay" term of Hormozi's Value Equation (studied 2026-06-29) applied to
   the page's literal render speed rather than its copy: shrinking Time Delay raises
   perceived value without touching price or content.
2. **Specimen-modal fonts deferred from an unconditional render-blocking `@import` to a
   lazy `<link>` injected on first modal open.** *Why it lifts conversion / speed:* cuts two
   blocking third-party font fetches off the critical path for every visitor, the large
   majority of whom never open the Brand Work specimen modal. Faster first paint for
   everyone, zero visual change for the minority who do open it (fonts still load,
   just on-demand instead of upfront).
